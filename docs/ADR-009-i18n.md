# ADR-009 – Többnyelvűség, next-intl, dinamikus nyelv hozzáadás

**Dátum:** 2026-08-16  
**Státusz:** Elfogadva  
**Döntéshozó:** Projekt architekt

---

## Kontextus

A platform multinacionális vállalatokat is kiszolgálhat, ahol a felhasználók különböző nyelveken dolgoznak. A rendszernek támogatnia kell többnyelvű UI-t és opciósan többnyelvű adattárolást. Új nyelveket üzemeltetési változtatás nélkül kell lehessen hozzáadni.

## Döntés

**Kétszintű lokalizáció:**
1. **UI i18n** – next-intl (frontend) + ASP.NET Core Localization (backend)
2. **Adat lokalizáció** – `*Translation` táblák (Phase 2+, opcionális)

**Konfiguráció:** tenant szintű alapértelmezett nyelv + felhasználói override.

---

## UI lokalizáció – Frontend (next-intl)

```
frontend/
├── messages/
│   ├── en.json    ← alap, mindig teljes, kötelező
│   ├── hu.json
│   ├── de.json
│   └── fr.json    ← később hozzáadható, újraindítás nélkül
├── i18n.ts        ← next-intl konfiguráció, támogatott locale-ok
└── middleware.ts  ← locale detection, routing (/hu/..., /en/...)
```

```json
// messages/en.json – struktúra
{
  "common": {
    "save": "Save", "cancel": "Cancel", "loading": "Loading...",
    "upgrade_required": "This feature requires an upgrade."
  },
  "riskRegister": {
    "title": "Risk Register",
    "createRisk": "Create Risk",
    "status": { "active": "Active", "archived": "Archived" }
  },
  "assessment": { ... },
  "errors": {
    "unauthorized": "You don't have permission.",
    "moduleNotLicensed": "Upgrade your plan to access this module."
  }
}
```

```tsx
// Komponensben
const t = useTranslations('riskRegister');
return <h1>{t('title')}</h1>;
// ❌ Tilos: <h1>Risk Register</h1>
```

## UI lokalizáció – Backend

```csharp
// Program.cs
builder.Services.AddLocalization(options => options.ResourcesPath = "Resources");

// Resources/
//   en.json, hu.json, de.json

// Handler-ben
public class CreateRiskHandler(IStringLocalizer<CreateRiskHandler> localizer)
{
    // Hibaüzenetek lokalizálva
    return Result.Failure(localizer["RiskTitle_Required"]);
    // ❌ Tilos: Result.Failure("Risk title is required")
}
```

## Nyelv kiválasztási sorrend

```
1. Felhasználói preferencia (UserPreferences.Language)
        ↓ ha nincs beállítva
2. Tenant alapértelmezett (TenantSettings.DefaultLanguage)
        ↓ ha nincs fordítás az adott nyelven
3. Fallback: "en" (mindig teljes)
```

## Dinamikus nyelv hozzáadás

```
Admin: "Új nyelv: Német (de)"
    ↓
1. messages/de.json feltöltése (vagy API-n keresztül)
2. TenantSettings.SupportedLanguages += "de"
3. i18n.ts frissítése (build nélkül: futásidős JSON betöltés)
4. Fordítási státusz dashboard: hiányzó kulcsok jelzése
```

## Adat lokalizáció (Phase 2+, opcionális)

Ha egy entitás mező (pl. `Risk.Title`, `Risk.Description`) több nyelven tárolható:

```csharp
// Translation tábla minta
public class RiskTranslation
{
    public RiskId RiskId { get; }
    public LanguageCode Language { get; }  // "hu", "en", "de"
    public string Title { get; }
    public string Description { get; }
}

// Lekérés: ha nincs a kért nyelven, fallback a tenant default nyelvre
public string GetTitle(LanguageCode language)
    => Translations.FirstOrDefault(t => t.Language == language)?.Title
       ?? Translations.First(t => t.Language == _tenantDefaultLanguage).Title;
```

## Következmények

- `en.json` mindig teljes kell legyen – ez a referencia és a fallback
- Minden új UI szöveg azonnal bekerül az `en.json`-ba, a többi fordítás késhet
- Fordítási kulcsok hierarchikusak, modulonként szeparálva
- Backend hibaüzenetek soha nem hardcode-olt angol szövegek
- Új nyelv hozzáadása: 0 kódmódosítás, csak JSON fájl és tenant konfig
